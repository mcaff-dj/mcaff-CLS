# Private per-cell comments on report pivot tables

Status: approved (chat design), pending spec review.

## Context

`api/_reports/mcaffeine.html` and `hyphen.html` (generated by `scripts/generate_report.py`
+ `scripts/gen_panels.py`, sharing `scripts/_shell_head.html`'s CSS/JS) are the actual
report HTML, but nobody reaches them directly: `GET /api/report/mcaffeine|hyphen` (see
`api/report/[card].js`) already requires a Google OAuth session (`api/auth/[action].js`,
`api/_lib/session.js`) *and* that the signed-in user's `session.perms` includes that card,
before it hands back a short-lived signed CloudFront URL to the real file. So anyone
looking at a pivot table is already authenticated — there is no "make viewing require
login" question here, and no view-gate to add or reason about.

The JS that runs inside the report executes same-origin with the rest of the app (the
dashboard iframes it through an Amplify `/reports/*` rewrite specifically so same-origin
JS/cookies work — see `api/report/[card].js`'s comments and `HomeClient.js`), so
`fetch('/api/auth/me')` and any authenticated API call from inside the report behaves
exactly like it does on `calling.html`/`onboarding.html`, which already do this.

The user wants to click any pivot-table cell, leave a note, and have that note follow them
across devices, visible only to them — not to anyone else who opens the same report,
including other logged-in users.

## Decisions (from brainstorming)

1. **Identity**: reuse the existing Google OAuth/session system verbatim. No new auth
   mechanism, no new gate — the session already exists by the time the report renders.
2. **Scope**: every `.pivot-table` in both reports, implemented once, generically — not
   wired per table in Python.

## Out of scope

- No comment history/threads — one note per (user, cell), overwritten on save.
- No comments visible to other users, no "share this note" — private means private.
- No commenting on non-pivot elements (charts, KPI tiles) in this iteration.
- No offline/optimistic queueing — a save while offline just fails with a visible error.

## Data model

New table, added to `api/_lib/db.js`'s existing `bootstrapSchema()` (same idempotent
`CREATE TABLE IF NOT EXISTS` convention as `users`/`permissions`/`mom_boards`):

```sql
CREATE TABLE IF NOT EXISTS report_cell_comments (
  id INT AUTO_INCREMENT PRIMARY KEY,
  user_id INT NOT NULL,
  page VARCHAR(255) NOT NULL,
  cell_key VARCHAR(255) NOT NULL,
  comment TEXT NOT NULL,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uniq_user_page_cell (user_id, page, cell_key),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
)
```

- `page` = `location.pathname` of the report as loaded inside the iframe (e.g.
  `/reports/mcaffeine.html` — the signed-URL path from `reportUrls.js`, not
  `/api/report/mcaffeine`, which only redirects there), naturally namespacing mcaffeine
  vs. hyphen and any future report reusing this shell. The signature lives in the query
  string, which is ignored — only the stable path is used as the key.
- `cell_key` = a client-derived string identifying the cell by content, not position:
  `<pivot title>␟<row label>␟<top column header>␟<sub column header>`
  (`␟` = unit separator, unlikely to appear in real labels). Stable across nightly
  regeneration since row/column labels don't change month to month, only the values do.
  Built by reusing the same header/row grid-expansion logic the existing generic CSV
  export (`_shell_head.html`'s `tableToGrid`) already runs over every `.pivot-table` —
  that function gets exposed as `window.tableToGrid` instead of being re-derived.

## API

One new consolidated dynamic route, following the existing `auth`/`admin`/`escalation`
`[action].js` pattern exactly, mounted in `api/_lambda/app.js`:

```js
mount('all', '/api/report-comments/:action', '../report-comments/[action].js', 'action');
```

`api/report-comments/[action].js`:

- **`GET list?page=<pathname>`** — requires session (401 if not signed in). Returns
  `{ comments: { [cellKey]: text } }` for `session.uid` + that page. One request per page
  load, not per cell.
- **`POST save`** `{ page, cellKey, text }` — requires session. `text` trimmed empty →
  `DELETE` the row (no separate delete action). Otherwise
  `INSERT ... ON DUPLICATE KEY UPDATE comment = VALUES(comment)`.

`db.js` gains `getCellComments(userId, page)` and `saveCellComment(userId, page, cellKey, text)`
following the existing function-per-table style.

## Client behavior

Added once in `_shell_head.html`, alongside the existing generic CSV-export script (same
"scan every `.pivot-table` on the page" shape), not per-table in `generate_report.py`/
`gen_panels.py`.

On page load:
1. `fetch('/api/auth/me')` (same call `api/_reports/calling.html` and `onboarding.html`
   already make from a static report page — same-origin, cookie flows automatically).
2. If authenticated, `fetch('/api/report-comments/list?page=' + location.pathname)` and
   keep the `{cellKey: text}` map in memory; mark every cell with a saved note (a small
   persistent dot, so existing notes are discoverable without opening each cell).

Interaction:
- Click any `.pivot-table td` (not header cells) → popover anchored to that cell, styled
  like the existing `.chart-tip` (surface/border/shadow tokens) but interactive
  (`pointer-events:auto`, stays open until explicitly closed) — a textarea prefilled with
  the existing note if any, plus Save and Clear buttons.
- Not signed in (session cookie expired mid-view — the only way to reach this, since
  `/api/report/[card].js` already requires a session before the iframe ever loads) →
  popover instead shows "Sign in to add a note" linking to `/api/auth/login?next=...`
  with **`target="_top"`** (same convention as `OnboardingClient.js`'s home-link). The
  report renders inside the dashboard's `<iframe id="reportIframe">`
  (`app/HomeClient.js`), and Google's OAuth page refuses to render inside a third-party
  iframe — the link has to navigate the whole tab, not the iframe, or login silently
  breaks. `next` points at `window.top.location.href` so it lands back on the dashboard,
  which re-embeds the iframe with a fresh signed URL once re-authenticated.
- Save → `POST /api/report-comments/save`, update the in-memory map and the cell's dot on
  success; a failed save (network/401) shows an inline error in the popover, note is not
  cleared so the user can retry.
- Clear → same endpoint with empty text; removes the dot.
- Closing: explicit Close button, `Escape`, or clicking outside the popover.

## Testing

- `db.js`: unit-style check that `getCellComments`/`saveCellComment` round-trip and that
  save-with-empty-text deletes.
- `report-comments/[action].js`: 401 when signed out; save/list happy path; save with
  empty text deletes an existing row.
- Manual: open a report via the dashboard (always authenticated) → add a note → reload →
  dot + note persist → open the same report on another device signed in as the same user
  → note appears there too → sign in as a different user → note does not appear. Separately,
  simulate the expired-session edge case (clear the session cookie via devtools without
  navigating away) → click a cell → confirm the sign-in link navigates the top window, not
  the iframe.
